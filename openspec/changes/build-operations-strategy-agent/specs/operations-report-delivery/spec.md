# Spec Delta

## Purpose

本能力用于向运营人员可靠地展示报告生成过程、专业运营报告、证据来源和历史版本，并提供安全访问与可编辑、可分享的导出结果。

## ADDED Requirements

### Requirement: 展示报告生成状态

系统 SHALL 展示运营简报确认、案例研究、策略设计、质量审查、完成和失败等用户可理解的任务状态。长时间运行期间，用户能够刷新或重新进入页面查看最新状态。

#### Scenario: 报告正在生成
- **WHEN** 用户提交并确认运营简报
- **THEN** 系统创建报告任务并展示当前阶段
- **AND** 用户离开页面后重新进入仍能查看任务状态

#### Scenario: 报告生成失败
- **WHEN** 报告任务因模型、搜索或系统错误失败
- **THEN** 系统展示失败阶段和可理解的错误说明
- **AND** 保留用户已确认的输入以支持重试

### Requirement: 提供结构化报告阅读体验

系统 SHALL 在 Web 页面中按报告章节展示运营方案，并支持目录导航。报告中的引用 SHALL 能够打开对应证据的来源链接，并显示来源主体、发布日期或未知标记以及访问日期。

#### Scenario: 用户阅读案例分析
- **WHEN** 用户查看报告中的案例事实或效果数据
- **THEN** 用户能够从该内容访问对应来源
- **AND** 能够识别该内容属于事实、推断、建议还是假设

### Requirement: 保存报告历史和版本

系统 SHALL 保存用户的报告任务及其正式输出。对同一运营场景重新生成或修改后的报告 MUST 形成新版本，不得覆盖此前已经交付的版本。

#### Scenario: 用户重新生成报告
- **WHEN** 用户修改运营简报并重新生成方案
- **THEN** 系统创建新的报告版本
- **AND** 用户仍可查看此前版本及各版本的生成时间

#### Scenario: 用户查看历史报告
- **WHEN** 已登录用户进入报告历史
- **THEN** 系统仅展示该用户有权访问的报告
- **AND** 支持按创建时间和运营场景识别报告

### Requirement: 导出可用的报告文件

系统 SHALL 支持将正式报告导出为适合分享的 PDF 文件和便于后续编辑的 Markdown 文件。导出内容 MUST 保留章节结构、关键表格、质量说明和证据引用。

#### Scenario: 导出 PDF 报告
- **WHEN** 用户选择导出 PDF
- **THEN** 系统生成包含完整正文和证据附录的 PDF 文件
- **AND** 页面内容不存在截断或章节缺失

#### Scenario: 导出可编辑报告
- **WHEN** 用户选择导出 Markdown
- **THEN** 系统生成可编辑文件
- **AND** 保留标题层级、表格和引用链接

### Requirement: 实施身份认证与访问隔离

系统 MUST 要求用户登录后访问报告功能，并确保用户只能查看和导出自己有权访问的任务、运营简报、证据和报告。

#### Scenario: 未登录访问报告
- **WHEN** 未登录访问者请求报告详情或下载文件
- **THEN** 系统拒绝访问并要求登录

#### Scenario: 用户访问无权限报告
- **WHEN** 已登录用户请求不属于其权限范围的报告
- **THEN** 系统拒绝返回报告内容和相关证据

### Requirement: 明确报告的决策支持属性

系统 SHALL 在 Web 报告和导出文件中说明报告用于运营决策支持，效果预测与资源估算需要结合实际数据验证，最终执行与业务决策由用户负责。

#### Scenario: 用户查看正式报告结论
- **WHEN** 正式报告展示策略建议、效果假设或资源估算
- **THEN** 报告同时展示适用条件和验证责任说明
- **AND** 不将预测内容表述为保证实现的业务结果
