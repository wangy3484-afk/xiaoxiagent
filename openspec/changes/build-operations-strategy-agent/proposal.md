# Proposal

## Why

公司运营人员在面对拉新、留存、活动和内容运营问题时，通常需要投入大量时间收集案例、分析业务并制定执行方案。普通大模型问答容易产生泛化建议、来源不明和无法落地的问题，因此需要建设一个具备专业运营方法、证据研究、场景适配和质量审查能力的运营决策支持 Agent。

## What Changes

- 支持拉新增长、用户留存、活动运营和内容运营四类场景。
- 接收用户的自然语言描述，并将其整理成结构化运营需求。
- 识别主要运营场景、辅助场景和需要解决的核心矛盾。
- 根据具体运营类型发起专业追问，补齐目标、用户、现状、资源、周期和指标等信息。
- 建立四类运营场景各自的分析框架、策略模板和质量标准。
- 实时检索头部企业及其他高相关企业的公开运营案例。
- 对案例来源、时效性、业务阶段和场景匹配度进行评估。
- 将案例拆解为目标、人群、触点、机制、激励、执行条件和效果证据。
- 区分公开事实、合理推断、策略建议和待验证假设。
- 根据用户实际资源和约束进行策略迁移，不直接复制头部企业做法。
- 生成包含诊断、策略、执行计划、指标、实验和风险的专业运营方案报告。
- 在输出前进行完整性、证据质量、适配性、可执行性和可衡量性审查。
- 通过 Web 应用提交场景、补充信息、查看生成进度并导出报告。
- Agent 仅提供决策支持，不接入内部用户数据，也不自动执行运营投放。

## Capabilities

### New Capabilities

- `professional-operations-intake`: 接收自然语言场景，识别运营类型，并通过专业追问形成结构化运营简报。
- `benchmark-evidence-research`: 检索和筛选公开案例，生成包含来源、时间、证据等级和适配度的案例证据。
- `operations-strategy-planning`: 使用拉新、留存、活动和内容运营专项方法，完成诊断、策略设计、执行规划及指标设计。
- `operations-report-quality`: 对报告的完整性、证据质量、适配性、可执行性和可衡量性进行独立审查。
- `operations-report-delivery`: 展示任务状态，提供报告阅读、历史查看和导出能力。

### Modified Capabilities

无。

## Impact

- 新增面向公司运营人员的 Web 应用。
- 新增结构化运营需求、案例证据、策略方案和质量评估等数据对象。
- 新增公开网络检索和大模型服务依赖。
- 新增有状态的运营分析与报告生成流程。
- 新增任务、证据、报告及生成记录的持久化存储。
- 新增容器化部署、基础身份认证和运行监控能力。
